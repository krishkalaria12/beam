Porting Beam from React + Tauri to GPUI

Replace the entire webview frontend with a native GPUI application, keep every feature and every keystroke on Linux, Windows and macOS, delete the theming system, and land a single fixed glass surface. The plan is built so that after one sequential foundation, up to seven and then ten streams of work run at the same time without touching each other's files.

01 — The move

Why this port is tractable, and why the last attempt drifted

Beam is not a React app with a Rust helper. It is a 36,382-line Rust application with a React face bolted on through 87 IPC commands. Every feature — clipboard history, the file index, the calculator, focus enforcement, the AI provider layer, snippets, hotkeys, the extension host — already lives in apps/desktop/src-tauri/src. The frontend's 85,000 lines are overwhelmingly presentation, IPC plumbing, React Query cache management, and serialization.

What the Windows and macOS backends changed about this plan

Going cross-platform made the port easier, not harder, because it forced the abstraction the GPUI side needs anyway. src/desktop/ (691 lines) is now a platform-neutral dispatch layer: DesktopBackendKind, WindowBackendCapabilities, ClipboardBackendCapabilities and one DesktopIntegrationStatus shape that all three backends produce identically. The GPUI frontend consumes that one shape and never branches on platform — exactly the contract the React frontend already has, where only two lines of TypeScript (a navigator.platform check for ⌘ versus Ctrl) know what OS they are on.

Three things did get harder, and each has a row in the risks table: the data directory assertion is now three assertions, the tray and global-shortcut replacements are now three implementations each, and "full parity" has to be defined per platform because several features are genuinely Linux-only by design.

The structural move

Decouple the domain modules from Tauri, then call them in-process from GPUI. AppHandle becomes &BeamContext. app.emit("ai-stream-chunk", …) becomes a typed event on an internal bus. tauri_plugin_store becomes a plain JSON store pointed at the same files. Result<T, String> reverts to the typed thiserror errors each module already defines — the String was only ever there to cross the IPC boundary. After that, the entire IPC layer, the React Query layer, and the serialization layer stop existing rather than getting ported.

The previous attempt lost coherence because there was no ledger. A port of this size has one failure mode: an agent or a person reaches a component, cannot find the original's exact spacing or keyboard behaviour, invents something plausible, and the invention propagates. Section 08 is the countermeasure and it is not optional — it is the difference between a port and a rewrite.

What GPUI gives you, and what you have to build

Read out of zed-industries/zed at crates/gpui, and cross-checked against zeronsh/comet, which is a shipping GPUI app with exactly the glass treatment Beam wants. Both are the reference material for this port; when a lane is unsure how to do something in GPUI, the answer is in one of those two trees, not in invention.

Pin discipline

GPUI is pre-1.0 and breaks between revisions. Pin gpui, gpui_platform and gpui_tokio to one git rev in [workspace.dependencies], record the rev and the reason in docs/parity/gpui-pin.md, and treat a bump as its own task with its own smoke pass. Comet's Cargo.toml shows what a well-documented pin looks like. Pin rust-toolchain.toml alongside it.

04 — Design direction

One surface, fixed: 36% glass

The theming system is removed, not simplified. There is no light mode, no style switch, no base-colour picker, no user CSS themes, and no Beam-branded palette to preserve. What replaces it is a single dark translucent surface in the register comet uses: the launcher sits over the desktop as a frosted plate, and the content reads as lightweight ink on top of it.

The glass ladder

"30–40% glassy" is a real number in this design: the shell plate is a tint at 0.36 alpha over a compositor-blurred backdrop, so roughly two thirds of the desktop reads through. Everything above the plate is a white wash, never a new fill — that is what keeps translucency from turning to mud as elements stack.

Glass mode detection

Resolve once at boot into GlassMode::{Frosted, Solid}. On two of three platforms this is a compile-time constant; only Linux has to probe, using the existing desktop::status and environment reporting.

  • macOS → always Frosted. Blurred maps to NSVisualEffectView. No fallback needed, ever.
  • Windows → always Solid. D9 Mica and DWM blur-behind are deliberately unused on every Windows version. This removes the OS-version detection branch entirely: Windows is one code path, not two.
  • Linux → Frosted on Hyprland, KWin, or any compositor advertising blur; Solid on GNOME/Mutter and on X11 without compositing blur.
  • BEAM_GLASS=off forces Solid anywhere, for screenshots and for users who want it.

One enum; every surface token derives from it. No per-widget branching, which is exactly the trap .sc-solid fell into across 52 KB of CSS — and exactly the trap a three-platform port would fall into twice as fast.

The Solid plate is not a degraded mode. It is the same geometry, the same radii, the same wash ladder, at a higher plate alpha — which is why the design has exactly two values and no third.

Rules that keep glass legible

  • No drop shadows on translucent fills. The shadow paints behind the fill and greys it. Use a 1px inset edge for elevation instead.
  • Wash, don't fill. Hover, selection and cards are white at low alpha, never a new opaque colour.
  • One layer per float. Popovers, dropdowns and the ⌘K panel paint in a single scene layer so a hover repaint elsewhere cannot reorder them under the plate.
  • Dividers at .08, borders at .14. Two values, no third.

Typography and metrics — transcribed, not redesigned

The type scale carries over exactly. The current app derives every size from a 13px base with fixed ratios; those become constants in beam-ui and the font-family picker in settings keeps working through the existing fontdb-backed settings::list_font_families.

05 — Target architecture

Seven crates at the repo root, one binary

Decision D6 puts the Rust at the top level in the standard layout. The result is an unambiguous split by language: crates/ is Rust, apps/ and packages/ stay bun. The root .cargo/config.toml that already exists — target-dir = "target/rust", plus the two Linux linker flags — keeps working untouched.

Why this ordering is better than the alternative

Because the crates are born at their final path in G0, apps/desktop is never migrated — it is simply deleted once, at cutover, with nothing left inside that anyone needs. The two trees coexist for the whole migration, which is exactly what rule R7 requires anyway: the React app stays buildable and runnable next to the GPUI one, and neither is in the other's way.

The paths that must be retargeted are known and small: the rust:fmt and rust:fmt:check scripts in the root package.json lose their --manifest-path apps/desktop/src-tauri/Cargo.toml and become plain cargo fmt --all; the desktop:* turbo tasks disappear along with the Vite build they wrapped; CI path filters and the three release workflows point at crates/; and the AUR, deb, rpm and NSIS recipes pick the binary up from target/rust/release/beam.

beam-services stays a single crate on purpose. Its modules already cross-reference each other (crate::desktop::… and crate::linux_desktop::… from clipboard, from applications, from focus); splitting them into per-feature crates would force an import rewrite across 36,000 lines and invite exactly the churn this plan is designed to avoid. Keeping the mod tree byte-for-byte identical is the lowest-drift move available.

Follow the façade that already exists

desktop/ is the pattern for everything platform-shaped in this port. Backends live behind it, produce identical serde shapes, and the caller never branches. Apply the same discipline to the three pieces the port has to build — tray, activation socket, deep-link registration — so beam-app calls platform::tray::upsert(…) and never sees an NSStatusItem. Where GPUI itself forces a branch (layer-shell versus PopUp), confine it to a single beam-app::window module with one public function.

06 — Sequence and concurrency

One narrow spine, then wide fan-out

Four gates. Each gate is a hard barrier: nothing downstream starts until the gate's acceptance check passes, and everything inside a gate runs in parallel. The gates exist because they are real dependencies, not because plans conventionally have phases.

08 — Anti-drift protocol

Nine rules that keep a port from becoming a rewrite

The failure mode of the previous attempt was not difficulty, it was drift: an unclear original, a plausible invention, and no mechanism to notice. These rules are the mechanism. They cost very little and they are the reason this plan can run ten lanes at once.

  1. One source file, one target file, one marker. Every ported Rust file opens with // PORT: apps/desktop/src/modules/todo/components/todo-view.tsx. A script greps every marker, diffs the set against the source tree, and fails when a source file has no porter and no waiver. Run it in CI from G1 onward. 
    # scripts/parity-audit.sh — fails on unported source files
grep -rho '// PORT: [^ ]*' crates/ | sed 's|// PORT: ||' | sort -u > /tmp/ported
find apps/desktop/src -name '*.tsx' -o -name '*.ts' | sort > /tmp/source
comm -13 /tmp/ported /tmp/source | grep -vf docs/parity/waivers.txt
  2. Transcribe metrics; do not re-derive them. When the original says py-2.5 gap-3 rounded-lg text-[13px], the port says .py(px(10.)).gap(px(12.)).rounded(px(8.)).text_size(px(13.)). Read the number out of the class. Never estimate a spacing value by looking at a screenshot.
  3. Pin behaviour with tests before removing Tauri. The A-lanes are mechanical, which is exactly when silent regressions slip in. Each service module gets unit tests over its current behaviour first, then the attribute comes off. The existing code has very little test coverage; this is where it gets added, and it is not optional scope.
  4. The frozen API list. The 87 IPC command names are written to docs/parity/api.md at G0 and each becomes a Rust function with the same name. Adding a function that has no IPC ancestor requires a one-paragraph note in docs/parity/adr/. This stops lanes from quietly inventing surface area.
  5. File ownership is exclusive. The ledger assigns every source file to exactly one lane. Two lanes never edit the same target file. Where a genuine shared need appears, it goes into beam-ui and Lane B owns it.
  6. Golden screenshots first. Captured at G0 while the React app still runs, committed, and never regenerated from the port. A screenshot taken after the fact proves nothing.
  7. Keep the React app buildable until G3. The branch runs both. When a detail is ambiguous, launch the old app and look — that is worth more than any amount of documentation, and it stops being available the moment you delete it.
  8. Sanctioned deviations are a closed list. The seven entries in §04 are the complete set. Anything else that differs is a defect. Anything on the list must not be reverted by a later lane that thinks it found a bug.
  9. Platform variance is data, not judgement. A lane never decides whether a feature should exist on a platform. The capability matrix in §02 and the caveats table in §07 say what is intended; the code says what is current. Where they disagree, that is an ADR, not a fix. Concretely: Soulver missing on Windows is correct, an empty window list on macOS without Accessibility is correct, and the hyprwhspr panel not existing off Hyprland is correct.

If lanes are run by agents

Give each lane exactly three things and nothing more: its ledger rows, the source files those rows name, and beam-ui's API. Do not give a lane the whole repository — breadth is what produced the confusion last time. A lane that needs something outside its rows files an ADR and stops; it does not improvise.

10 — Definition of done

What "full parity" means, concretely

Functional — per platform

  • All 21 panels reachable and matching their golden screenshots, allowing only the §07 caveats.
  • All 87 former IPC commands available as service functions and exercised by the UI.
  • All 46 extension node types render; the fixture extension passes on each platform.
  • Every keyboard binding works identically, with ⌘ on macOS and Ctrl elsewhere.
  • Trigger symbols, aliases, hotkeys, pins, hidden commands and fallback commands all behave as before.
  • beam, beam --toggle, beam --run-command, beam dmenu and both deep-link schemes all work on each platform.
  • Linux extras intact: GNOME shell extension, KDE bridge, wayland helper, udev snippets rule.
  • macOS: Accessibility permission prompt, status, and the degraded states that depend on it.
  • Windows: Start Menu and registry app discovery, foreground tracking, SendInput expansion.
  • Browser extension bridge functions on all three.

Non-functional

  • Upgrade preserves every database, store file and keyring entry, on each platform.
  • Hotkey-to-painted-window under 80 ms on a cold window.
  • Cold start no slower than the current build.
  • Resident memory below the current webview build.
  • Linux packages build with no webkit2gtk; Windows installers with no WebView2 bootstrapper; the macOS .dmg is signed and notarized and opens without a Gatekeeper prompt.
  • Frosted glass on macOS and on blur-capable Linux compositors; Solid on Windows, GNOME/Mutter and bare X11 — legible in every case, same geometry throughout.
  • Zero tauri and zero tauri-plugin-* imports anywhere in the tree.
  • cargo check green on all three CI runners.
  • parity-audit.sh reports no unported source files outside the waiver list.

Start here

Every decision is closed. Nothing is waiting on anyone. Three platforms cut over together, macOS ships, Windows takes Solid glass, upstream GPUI, no mermaid or math, opacity survives as Glass strength, user themes are gone, and the crates live at the repo root.

Run G0 as a single sequential stretch: create the root crates/ workspace and pin the toolchain and GPUI rev, wire cargo check on three CI runners, build BeamContext with the three asserted data paths, write the window module with all four surface paths, swap the macOS hotkey to global-hotkey, resolve the three spikes, and capture per-platform golden screenshots. Everything after G0 is parallel — seven lanes, then ten. The plan's value from here is entirely in resisting the urge to start a panel before the spine exists, and in keeping the ledger honest once ten lanes are running at once.
